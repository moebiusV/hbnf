# COBOL in HyperBNF

`cobol.hbnf` is COBOL (ISO/IEC 1989) in free-format source: the identification, environment, data and
procedure divisions, the data description clauses, and the statements a program is made of, with the
standard's own rule names where it has one.  `cobol-words.hbnf` holds the tokens (words, literals, the picture
string, white space and comments) and `reserved.hbnf` the reserved words, generated by
`tools/cobol_reserved.py` from GnuCOBOL 3.2's `cobc/reserved.c` (the words its comments mark as the 1985, 2002,
2014 or 2023 standard; vendor extensions are left out, so a program may name a field with one).

The aim is the one of `RFCPLAN.md` step 20: a grammar that reads like the BNF of the standard.  What stays
simple:

- **Noise words and the many optional phrases** are brackets: `[ "IS" ]`, `[ "ROUNDED" ]`, `[ "ON" ] "SIZE" "ERROR"`.
- **A statement list ends where the next word is no verb.**  A reserved word is no name, so `ELSE`, `END-IF` and
  the verbs end a list of operands without a rule for it, and the optional scope terminators (`END-ADD` and the
  rest) need no guessing.
- **Abbreviated conditions** (`IF A > B AND C`, `IF X = 1 OR 2`) and **level-88 condition names** read the same,
  as a bare operand, and the tree has one node for both.  Which it is depends on the data division; a checking
  pass tells them apart, and the parser does not have to.
- **Hyphens** make `A-B` a name and `A - B` a subtraction: the blanks decide, with no rule for them.

## What is read

Free format only.  Programs (nested ones too), the four divisions, `FILE-CONTROL`, `SPECIAL-NAMES` and
`REPOSITORY`, the data description entries (`PICTURE`, `USAGE`, `VALUE`, `OCCURS`, `REDEFINES`, `RENAMES`, `SIGN`,
`CONSTANT`, level 88), the report section (`RD` and its groups) and the screen section, `DECLARATIVES`, and the
statements `ACCEPT ADD ALLOCATE ALTER CALL CANCEL CLOSE COMPUTE CONTINUE DELETE DISPLAY DIVIDE ENTRY EVALUATE
EXHIBIT EXIT FREE GENERATE GO GOBACK IF INITIALIZE INITIATE INSPECT MERGE MOVE MULTIPLY OPEN PERFORM READ
RELEASE RETURN REWRITE SEARCH SET SORT START STOP STRING SUBTRACT SUPPRESS TERMINATE UNSTRING WRITE`, the
conditions (relation, class, sign, abbreviated, combined) and arithmetic expressions with subscripts, reference
modification, `LENGTH OF` and `FUNCTION`; and the XML and JSON statements (`XML GENERATE` and `PARSE`, `JSON GENERATE` and `PARSE`).  A compiler directive (`>>` to the end of the line) and a `$` line
are read as comments.

Fixed format is `cobol-fixed.hbnf`, which includes this grammar and replaces the white space, the literals and the word characters with ones that know the columns (`where (col ...)`, CONTEXTS section 24); it is read with `--root=compilation-group`.  Not yet: `COPY` and `REPLACE`
(a preprocessor's work: textual inclusion and replacement that can happen between any two tokens, so it belongs
with the C preprocessor item of `RFCPLAN.md`, as one include-and-replace layer), the
object-oriented features and the rest of the vendor extensions.  This is a core, not the language; a size
comparison with GnuCOBOL's `parser.y` waits until it is the language.

What the grammar leaves to a later pass, on purpose: types.  A `PICTURE` and a `USAGE` are kept as written, so
`COMP-3` is the text `COMP-3` and nothing is inferred (a decimal that is read as a float rounds); the checking pass
that derives the type from them is where the exactness is kept.

## Checked against GnuCOBOL

`sh tests/cobol.sh` generates the parser and runs it over `tests/good` and `tests/bad`.  `sh tests/cobol-scan.sh`
goes further: it takes the programs of GnuCOBOL's own test suite, which `tools/cobol_fetch.sh` fetches and
`tools/cobol_extract.py` writes out in free format (they are fixed format and GPL, so they are fetched and not
kept here; a tab goes to the next multiple of 8 columns and a continuation line is joined to the line before it, a continued literal going on after the quote that opens the continuation), and counts those `cobc` accepts that the parser refuses.  The programs that change their format with a `>>SOURCE FORMAT` directive are left out: switching format in a file is what a switch of grammar is for.  The same scan runs over the NIST COBOL-85 validation suite (public domain), which `tools/cobol_fetch.sh` also fetches: `tools/cobol_extract_nist.py` replaces the suite's `XXXXXnnn` placeholders and applies the line patches GnuCOBOL's own tests give it, as EXEC85 does, and converts the 459 programs (`tests/cobol/nist-baseline.txt` is its number).  The ProLeap and Koopa test sources were looked at and add nothing: Koopa's COBOL-85 files are this same suite, and of ProLeap's 252 small test programs `cobc` accepts 16.  The number of them is
`tests/cobol/scan-baseline.txt`; it must not grow, and `scripts/cobol-scan.sh` lists them.  A program that uses `COPY` or `REPLACE` is listed apart, not counted: they rewrite the text before the grammar sees it (the preprocessor layer of `RFCPLAN.md`).

The other side of the comparison, programs the parser accepts and `cobc` refuses, is almost all semantic: an undefined
or ambiguous name, a redefinition, a `MOVE` between incompatible items, `OCCURS` under a variable-length group, a
missing file description, the wrong number of `CALL` arguments.  Those belong to the checking pass, which needs the
data division's declarations; the grammar does not try to refuse them.  The few syntax errors among them (`OCCURS` on a
level-01 or 77 item, the communication section's `SEND`) are not yet refused.  Where `cobc` is
installed it must agree on every file: it accepts each good one and refuses each bad one with
`cobc -free -fsyntax-only` (a bad file is one the compiler also refuses).  GnuCOBOL 3.2 comes from the
Debian `gnucobol3` package; its source, for `reserved.c` and `parser.y`, is
<https://ftp.gnu.org/gnu/gnucobol/gnucobol-3.2.tar.xz>, kept in `bench/cache/cobol` (not in the repository).

Finding the mistakes in the test programs themselves is part of what the compiler is for: it refused
`ADD 1 2 3 TO A B GIVING C` and `WHEN 6 7`, which are not COBOL.

## The generator

Two limits of the generator showed here, both for the reserved words, and both are gone.  A token exception
(`word - reserved-word`) builds one automaton, and the bound on its size was 2,000 states; the 413 reserved
words, as a trie, are 1,800 nodes before the automaton is minimized to about 800 states, so the bound is now
100,000.  A lookahead (`!`) could look at a literal or a token but not at a rule that is matched as a word;
now it parses the rule where it stands and puts everything back, in all four backends.  And a
case-insensitive literal in a rule of characters was one branch for each of its spellings, so a word of more
than four letters could not be one; each letter is now both its cases at one position, and a word is one branch.

## The gaps that are left (2026-11-13)

What cobc accepts and the parser refuses, by the scan (`tests/cobol-scan.sh`; the baselines are 2 in free format, 0 for NIST in free
format, 1 for NIST in the fixed format).  Each is a kind of thing, not a typo:

| program | what it needs | where it waits |
|---|---|---|
| `run_fundamental-076` | conditional compilation, `>>IF P64 SET`, `>>ELSE`, `>>END-IF` | the source stack (a preprocessor): the rewrite and the contexts it reads are in C, Rust and Zig, Ada follows |
| `syn_misc-065` | the GUI screen extensions of ACUCOBOL (`LIST-BOX`, `MODIFY`, `DISPLAY FLOATING WINDOW`) | left out, as the vendor extensions are |
| `NC205A` (fixed) | a word cut at the end of a line and continued after the `-` of the next (`PROCEDURE` and `DIVISION` are one name, `PROCEDUREDIVISION`) | the scanner of a word in the fixed format: the header of `cobol-fixed.hbnf` says so |
