Mustache templates in HyperBNF

mustache.hbnf is the syntax of a Mustache template: text, {{name}}, {{{name}}}, {{&name}}, {{! comment }}, {{> partial}}, {{#section}} ... {{/section}}, {{^inverted}} ... {{/inverted}}, {{=<% %>=}}, and nothing of how a template is rendered. Nineteen rules.

grammars/template.hbnf is a different, smaller Mustache grammar: the one the project renders its own code templates with (hbnf_template_syntax*.ad[sb] are what hbnf makes of it). It reads a section as a tree (block = open template close) and checks in the renderer that the closing tag names what the opening one did, so it uses no back-reference; it reads a partial and a change of delimiters as tags that the renderer refuses; and it allows blanks between {{ and a sigil, as the library it replaced did, where this grammar follows mustache.js and does not.

A closing tag has to say the name the opening one did. That is not context-free, and it is what the back-reference is for: name as tag keeps the text a name matched, and $tag is that text again, later in the same sequence. It is local to the rule, so {{#a}}{{#a}}x{{/a}}{{/a}} closes each section with its own tag, and a backtrack restores it with the position. The same two forms write XML's <a> ... </a>, a here-document's terminator and a raw string's delimiter (tests/backref.sh).

The details follow mustache.js: the sigil (# ^ / ! > & =) comes right after the {{, so {{ /a}} is a variable called /a; a variable is anything up to the first }}, with a } allowed inside it, but not nothing; {{{x}} is a variable called {x.

Checked against chevron

sh tests/mustache-diff.sh [N [SEED]] (needs a python with chevron installed, PYTHON=) generates random valid templates and mutations of them (a character deleted, inserted, replaced, swapped, doubled, the text cut) and asks the parser hbnf makes and chevron.render about each (tests/mustache/oracle.py). With 6,000 and 6,000: every valid template accepted, and the same answer on 5,984 of the 6,000 mutations; the other 16 are one case, a tag whose text holds a {{ ({{>a{{ }}), which hbnf reads to the first }} as mustache.js does and chevron refuses. The oracle is chevron plus two rules it lacks: a tag with nothing in it ({{#}}) is an error, and so is a {{ that is never closed (chevron lets it end the text, mustache.js says "Unclosed tag"). Finding those, and the generator's own mistakes (it put blanks before sigils, which mustache.js does not allow), is what the test is for.

Not done: {{=<% %>=}} is read as a tag but does not change the delimiters.

In Tree-sitter (`sh tests/treesitter.sh corpus/mustache/mustache.hbnf corpus/mustache/tests/good corpus/mustache/tests/bad`) the grammar generates with one declared conflict and parses all 25 good templates and shows an error on all 13 bad ones. A Tree-sitter grammar cannot make a closing tag repeat the opening one, so the backend writes as and $tag with an external scanner (--ts-scanner=FILE, the scanner.c that goes in src/): the scanner keeps each captured name in its state, which Tree-sitter saves for every fork, and accepts the closing name only if it is the same text. Without the scanner the closing name is any name, and the five mismatched bad cases ({{#a}}x{{/b}}) parse; on 2,000 mutations that left 106 templates only Tree-sitter accepted. With it, hbnf and Tree-sitter give the same answer on all 2,000 (1,339 accepted by both, 661 refused by both; `TSD_GRAMMAR=corpus/mustache/mustache.hbnf TSD_ORACLE=tests/mustache/oracle.py TSD_EXT=mustache sh tests/treesitter-diff.sh 2000 2`).

Running it found three faults in HyperBNF, now fixed: a lookahead inside a rule that is only text was silently dropped when the rule was compiled to its automaton; a rule used only in a lookahead was left out of the generated parser; and an alias of an optional token (blank_2 = blank) failed on nothing, where blank succeeds on it.
