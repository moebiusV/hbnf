IMP72 corpus

The source of the IMP72 compiler, as distributed through the DECUS library: a real metacompiler, written in its own language, that bootstraps from a small syntax reader (rsyn.imc) and a file that defines the language (syntax.imc). It was to be test data for hbnf in the way corpus/rfc/ and corpus/posix/ are. It is the subject of METACOMPILERS.md, which compares it with META II, SNOBOL4 and hbnf and asks what it would take for hbnf to play the part of its kernel.

Layout

corpus/imp72/
  README.md        this file
  SHA256SUMS       the hash of every file in tape/, as taken
  tape/            the files of DECUS 10-198, unchanged

tape/ holds the 30 text files of the program (`cd tape && sha256sum -c ../SHA256SUMS`). They are byte-for-byte what the archive serves, including the DEC-10 text conventions (CRLF line ends, upper case):

files what
syntax.imcthe syntax and semantics of the language, in syntax statements: 177 statements in 30 classes, as tools/imp72_to_hbnf.py counts them
impsyn.imcthe extra syntax the compiler's own sources are written with
rsyn.imcthe bootstrap: a reader for a tiny built-in syntax-statement notation, and the fourteen routines that enter productions into the syntax graph
lex, parse, graph, ercorinput and lexical analysis; Irons's parser; the syntax graph; error repair and ambiguity
cotree, entree, dosem, stackthe code-generation tree and special-case matching; semantics; the semantic stack
impsem, impm, dir, free, debugmachine-independent semantic routines; the driver; the directory; free storage; debugging
code, code2, code3, amod, rmod, omodPDP-10 code generation, assembly, register allocation, relocatable object output
tbin.iml, tprin.iml, traed.iml, fortio.mac, fortio.hlpthe I/O library: IMP and PDP-10 assembler
imp.rnothe source of the reference manual (RUNOFF)
r.cmd, 198.infthe loader command file; the tape's one-line description

The binaries on the tape (imp.low, imp.shr, implib.lib: the compiler and the library, as PDP-10 memory images) are not here. They are not text, hbnf has no use for them yet, and the archive keeps them (see below).

Status: cancelled

On 2026-10-22 the work was cancelled: IMP72 gets its own compiler, and hbnf will not read or bootstrap it. The files stay as the subject of METACOMPILERS.md. What exists: the tape's files with their hashes, this note, and tools/imp72_to_hbnf.py, which reads the syntax statements of syntax.imc and impsyn.imc and writes a HyperBNF grammar of them. A first run of that grammar through hbnf stopped on things hbnf does not have yet (~ negation for the comment rule, decision 11; an alias of a list rule) and, before that, reported a dozen unions whose alternatives it cannot tell apart, which is the ambiguity the measurement was after. The numbers are not final, and are not recorded here, for that reason; the converter re-runs in a second.

What it was for

syntax.imc is a compiler's language, defined by 177 productions each carrying its semantics, in a notation (<CLASS> ::= elements ::= semantics ;) that is one of the family hbnf reads. Reading it was to be the first measurement in METACOMPILERS.md: what hbnf makes of it, and in particular how many of its ambiguities hbnf's union analysis finds, because IMP72's syntax is ambiguous on purpose and resolved by rule. The other modules are the IMP source that a translator written with hbnf would have had to read; each of them was to parse, as every corpus/rfc snippet's vectors do.
