RFC 9112: request-line

rfc9112-1.bnf is request-line (section 3) and the rules it uses: RFC 9112's own, then the five it takes from RFC 9110 (token, tchar, absolute-path, uri-host, port), then RFC 3986's by the include. rfc9112-1.hbnf is the same text with the line dialect abnf and the changes below, each marked ; hbnf:. <id>.vectors/ holds six rules' inputs; request-line (22 inputs) runs in all four backends.

What hbnf says to the RFC's text

Two prose-vals, each with what it probably means:

hbnf: rfc9112-1.bnf:33:17: not written yet, in `uri-host`:
<host, see [URI], Section 3.2.2>
  `<...>` names a rule, as Backus and Naur write a nonterminal (ABNF also
  uses it to describe a rule in words), and no rule of that name is
  written.  Write it: `<host, see [URI], Section 3.2.2> = ...` at the
  start of a line.
  This probably means the rule `host`, defined elsewhere: write
  `uri-host = host`, and `include` the file that defines it
  uri-host      = <host, see [URI], Section 3.2.2>
hbnf: rfc9112-1.bnf:35:17: not written yet, in `port`:
<port, see [URI], Section 3.2.3>
  ...  This says `port` is defined elsewhere, and this rule has the same
  name: `include` the file that defines it and delete this line.  (A later
  `=` replaces an earlier one, so keeping it would replace the real rule
  with nothing.)

RFC 9110 defines uri-host and port by pointing at RFC 3986 ([URI]).

The .hbnf

  • uri-host = host, the rule the prose-val names.
  • port = <port, ...> is left out. A later = replaces an earlier one, so it would replace RFC 3986's port = *DIGIT, the rule it points at.
  • request-target stays |, in the RFC's order: absolute-form before authority-form. example.com:80 is an absolute-URI (example.com is a valid scheme) as well as an authority-form, so the two can match the same text. The RFC says authority-form is used only by CONNECT, which the method decides and this rule cannot see (a %where { } block, RFCPLAN.md decision 13, could ask it). The language is the same; the form recorded for CONNECT example.com:80 is absolute-form.
  • tchar is the RFC's.

HTTP-name = %s"HTTP" needed nothing: %s is HyperBNF's own spelling of RFC 7405's case-sensitive string, and the vectors check that http/1.1 is refused.
