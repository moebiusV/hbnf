HyperBNF and ABNF

hbnf (named for Hartmeier, Brauer, Norby and Floeter, and read as HyperBNF) is not ABNF. It borrows ABNF's rule notation (RFC 5234, and RFC 7405's case-sensitive strings) and builds a different language on it. It extends the notation downward, below characters to code points, octets and bits, and upward, to types, trees and hand-written scanners. It also folds the lexer into the grammar: there is no separate token stage to specify. This document sets out that relationship precisely:

  • what hbnf keeps from ABNF;
  • what it adds;
  • what it leaves out, by design or not yet;
  • where it keeps ABNF's spelling but changes the meaning;
  • for each layer of the design, what the code does today.

Statuses were checked by running them against this tree. Each ABNF construct was written as a two- or three-rule schema and pushed through the schema parser, the C emitter and gcc, then through the generated parser on accepting and rejecting inputs. The C, Rust, Zig and Ada backends are checked end-to-end by tests/e2e.sh and tests/portable.sh, run in the ada-toolchain:edge-full container (gcc-gnat, g++, rust and zig).

Backends

The four compiled backends are C, Rust, Zig and Ada. Planned, not yet implemented, the rest of the compiled targets: D, Fortran, Free Pascal, Nim, Odin, Objective-C, ATS and V — and, beyond those, the garbage-collected languages Go, Java, JavaScript, C#, F#, Julia, Common Lisp and newLISP.

A fifth output is not a language but a grammar for another tool: --backend=tree-sitter writes the grammar.js the tree-sitter generator reads. A phrase rule becomes seq/choice/repeat/optional; a character rule (a token in hbnf) becomes one regular expression (a choice among single code points is one class); the file's ws rule becomes extras; a rule that can match nothing, which tree-sitter refuses, is defined by what it matches that is not empty and named with optional; a rule that is only a choice among other tokens (label = identifier / digits) stays a choice of rules, so the parser, not the lexer, decides. What tree-sitter cannot say is left out and listed in the file's head and as warnings: context tests and bindings, actions, scanners written in C (unless --ts-scanner=FILE is given, see below). Two things have a form with an external scanner, and --ts-scanner=FILE writes it (the externals in the grammar.js and a scanner.c for src/): a back-reference (x as K ... $K: the scanner holds the captured text in its state and accepts only the same text again, as Mustache's closing tag needs; the tagged name must be a token the C backend scans as an automaton, with no limit on how many are open: the scanner's state is one number, the top of a stack of tags kept in memory the scanner owns, so a saved state is only good with the parser whose scanner made it), and a lookahead !x / &x of literals and such tokens (a zero-width token that looks at the text, and takes a literal that follows it into the test). Where several lookaheads could hold at once, the first that does is taken. Ordered choice has no form in tree-sitter: --ts-ordered gives each alternative a prec.dynamic (the first the most), and --ts-conflicts=a,b;c,d declares the groups of rules tree-sitter may fork between, which tree-sitter generate names one at a time (tests/ts-build.sh loops until it succeeds). Checked with the real generator: ALGOL 60 needs 4 conflicts, parses every program of tests/algol60 and 500 of 500 random sentences of the Report (tests/treesitter.sh, tests/treesitter-diff.sh; they need a tree-sitter binary and a node, and skip without them). Most of grammars/ and corpus/rfc generate too.

The C backend is pinned to C99 (OpenBSD-kernel compatible) and always emits code that C++ can consume directly — valid C++11 onward, no modification and no shim — so a C++ codebase can use a generated parser as-is. Should C++ support ever need more than that (idiomatic C++ types, exceptions, anything beyond a simple extern "C" header guard), a separate C++ backend takes over rather than complicating the C backend.

1. The shape

Borrowed from ABNF: the rule syntax — name = elements, concatenation, ( ), [ ], n*m repetition, "…" literals, ; comments. Alternatives are separated by |, ordered choice, as in PEG and as parse.y grammars are read. ABNF's / (union) is taken wherever ordered choice, in some order of the alternatives, accepts the same language (§3.2); the other steps in RFCPLAN.md let the rest of an RFC's ABNF compile as written. The reader takes RFC 5234's other forms: =/, %d13.10 (under dialect abnf; hbnf writes 13 10), *m, a rule going on to an indented line, newlines inside ( ) and [ ], and <prose-val>.

Extended downward (design): a schema can describe input below the token:

  • characters, through character-level rules and named character classes;
  • code points, with UTF-8 decoded on input;
  • octets and bits, through name:N bit fields.

In that design the lexer is not a stage of its own. Token definitions are grammar rules — character-level ABNF or a hand-written scanner action — and the scanner is generated from them.

Extended upward (implemented):

  • a rule's name is its type, and the tree's shape is read from the rules;
  • typed core rules (str, word, int, u16, flag, …);
  • scanner actions (scanners written in the target language, inside the schema);
  • schema directives and code blocks;
  • --idref output for OpenBSD daemons, and the runtime they link (runtime/hbnf_conf.h and .c) under a parse_config the grammar writes in its epilogue.

Same spelling, different meaning: alternation is ordered choice (PEG), not ABNF's union; literals are case-sensitive, like parse.y keywords; a rule referenced for a field is a type, not just a pattern.

Left out: nothing in RFC 5234's syntax is refused by the reader now. Character classes are named rules (grammars/common.hbnf). Some ABNF features are not there yet in the backends (§3).

Generated names carry a prefix

Every identifier hbnf generates from a rule is prefixed, so no rule is ever a reserved word of the language generated and nothing is renamed one name at a time. The prefix is the dialect the file names (dialect ybnf, --dialect=, --abnf, --ebnf), and bnf_ when it names none: the rule if is ybnf_if in a YBNF file and bnf_if in a file with no dialect line, in the C types, functions, enum constants and struct fields and in the Rust, Zig and Ada names. The built-ins (word, int, str, u8, ...) and ws keep their names. Messages always show the rule as the grammar writes it.

prefix none (a line in the file, or --prefix=none) turns the prefix off, so the generated names are the rules' own; the nine daemon grammars say so, because their action code and the programs they link against use the generated names. (prefix "pf_" and --prefix= still put their own prefix on the C types, in front of this one.) The two renames hbnf used before, atom to atom-rule and WORD to WORD-rule, remain only under prefix none and for a file with no dialect line that opts out; a prefixed name cannot collide with a built-in.

Tokens: a rule that is only text is one string

A rule with no named children has nothing for a tree to say, so hbnf does not build one. A rule is text when it is made only of literals, classes, groups, alternatives and repetitions, and of other rules that are text, with no built-in type (int, word, ...) and no code inside it, and when its file skips no whitespace inside it. A text rule is one token: hbnf builds a deterministic automaton from it, the generated scanner takes the longest text that ends in an accepting state, and its value is that text, a string. `scheme = ALPHA *( ALPHA / DIGIT / "+" / "-" / "." ) and path = *( "/" segment )` are strings, not lists of nodes; x = 1*( "a" / "b" ) is a string, not a list of empty nodes. A token that can match the empty text succeeds on it.

What is not text keeps its tree, on purpose:

  • an enum (dir = "in" | "out") is an enum, and a lone literal is its string;
  • a rule that names a built-in (int is a number, word a typed word) has a typed value in it;
  • a rule that refers to an exception (a - b) has its own form, below;
  • a rule in a file that skips whitespace, with more than one element or a repetition, skips whitespace between them (and between the entries of a repetition), which a token cannot; and a letter-led literal in a grammar with keywords is matched as a word, with its boundary, not as characters;
  • a rule whose automaton would be too large (a repetition bound past 32, or over 2000 states) is not approximated and stays a tree.

None of the nine daemon grammars changes: their text-like rules were already strings or enums. In dialect abnf and any file that says whitespace none, every pure-text rule is a token, which is what an RFC's lexical rules are.

The exception

x = a - b is what a matches, unless b matches exactly that text. It comes in two forms, and hbnf picks the form from the operands, so the notation is the same.

A token exception is for operands that are text hbnf can read exactly: a built-in scanner (word), a rule of characters, or a rule made only of literals, classes, groups, repetitions and other such rules, in a file where no whitespace is skipped inside it. Each such operand is read as a token: hbnf builds a deterministic automaton from the text, and the generated scanner, in all four backends, takes the longest text that ends in an accepting state. It decides nothing by looking ahead and makes no choice, so no grammar can be ambiguous or in conflict through it. x scans a, then asks whether b matches exactly that text, by scanning b with the end of the input moved to where a stopped. So word - reserved rejects if and accepts iff. An operand that cannot be one token (it refers to itself, bounds a repetition past 32, needs more than 2000 states) is not approximated; the exception is then a phrase exception.

A phrase exception is for the rest: an operand that is a rule with several elements in a file that skips whitespace between them, or one that contains a %scan or a built-in the automaton cannot see into. x parses a with its own parser, which builds a tree; then it tries b on the same text, with the input cut off where a ended and b required to end there too, and throws the trial's tree away. If b matched the whole of it, x fails and the position and the tree are put back, so the enclosing rule's ordered choice goes on as if x had not matched. Whitespace inside the operands is skipped as it is everywhere else in the file. The message says ` a that is not b . x` has a's type. A built-in (word) on one side of a phrase exception has no rule to parse, so hbnf says to give it one: w = word.

Neither form is a language difference in the sense of ISO 14977, which would also take shorter matches of a: this is the committed match, which is what a reserved word needs.

Not defined for a longer text (~"ab"), a built-in, or a rule that is not one character; the message says which. A hbnf extension: ABNF has no negation.
Comma list n#m element, #element# is * with an implicit comma separator: n#m is comma-separated repetition, #element is 1#element, sugar for element *("," element). Inherits parse.y's list semantics (no trailing comma, no empty elements); deliberately stricter than HTTP's #rule, which allows empty elements. Built (2026-10-18, C and the others: it is read into ordinary rules). In the Report's ALGOL 60 it is every list rule (corpus/algol60/algol60.hbnf). The same list written as a rule is xs = xs "," x | x, a left-recursive loop; # is that, inline.
dialect, --dialect=, --abnf, --ebnf, whitespace none, sensitivity string %i, --root=RULEper file; CLI dialect bnf \| ebnf \| abnf \| ybnf \| hbnf, a line like language and include, names the notation the file is written in; hbnf is the default. The notation decides how a code point and a case marker are spelled. In hbnf's own notation (no dialect line, or dialect hbnf) a file writes 0x41, 65, 0b1000001, 0x41..0x5A, i"abc", s"abc" and r"…", and %x, %d, %b, %o, %u, %i, %s are refused with a message that gives the new spelling (they are still read in a rule of bit fields, where 0x05 is a constant). Under dialect abnf or --abnf it is the other way round: RFC 5234 and RFC 7405 define the % forms, so 0x41, i"…" and r"…" are refused with a message that gives them; dialect bnf, ebnf and ybnf read the % forms as before and have none of the new ones. tools/hbnf_modernize.py rewrites the old spellings of a file in hbnf's own notation. The sensitivity string %i directive keeps its %i. In hbnf = defines a rule, := a rule with parameters (binary(N in level) := ..., a hyperrule) and ::= a domain (level ::= 1..17, kind ::= "int" \| "string", any ::= level \| 20, a metarule: a finite set of numbers or words for a parameter to range over; one that names itself is refused). A file in BNF, where ::= or := defines an ordinary rule, says dialect bnf; a ::= that no parameter uses is reported with that hint. dialect abnf reads the file as RFC 5234 reads ABNF, and --abnf (or --dialect=abnf) does the same for every file of a run: nothing is skipped between a rule's elements (whitespace none), a string is case-insensitive (sensitivity string %i), and a backslash in a string is a backslash ("\" is one character). The two directives may be given alone. A literal with no letters is never marked case-insensitive. In a grammar with no word/atom and no keywords, a letter-led literal is its characters, not a keyword; a case-insensitive one matches either case, and inside a character rule each letter is both its cases at one position, whatever the length of the word. hidden nl gap (a line) or hidden nl = ... (at the rule) names a rule that is only text and is to be matched and kept out of the tree: the rule that uses it has no field for it, in any backend, so no copy of its text is made, and a repeated or optional use of it is hidden too; for a hyperrule it hides every instance, and the grammar's start rule and a rule that builds structure cannot be hidden. In the C backend a string in the tree is a slice of the input (hbnf_sp(v) is its text and hbnf_sn(v) its length, packed in the 8 bytes a pointer takes), copied only when an escape has to be undone or it is 65535 bytes or more, and a rule that is only a choice among other rules is a union with the number of the alternative taken (_alt, from 1); --no-views keeps the copies, which --writer, --ast, --ast-tools, --idref, --forks, --compare, grammars with bit fields and grammars with context code that names the node (%where { }, %bind { }; x ? C, %bind C += x and code that only reads the text keep slices) always do. --root=RULE generates from the named rule instead of the first. Three things the reader does to an RFC's text so it need not be edited: a rule named like a built-in type (atom, word, str, int, bool, flag, uN, iN) that builds a structure is called <name>-rule, in the tree too, with a notice; a range in a rule that also names other rules becomes a rule of its own (dtext-x21-5A); and a union that needs backtracking is first-match-wins (above). The list container is the one place the generated C is driven by grammar-supplied fragments: the layout_ops { … } block names each list operation and its C text, so the daemon grammars take OpenBSD's TAILQ_* from layout tailq instead of #defineing macros in the preamble. hbnf's own structures are plain C — the default list is a head/tail singly-linked list written directly, and the arena chunk size is an enum, not a #define.

6. Whitespace uses ABNF's names

Where RFC 5234 has a name for a whitespace or line token, hbnf uses it rather than inventing one:

Name used earlier ABNF name
SPACE SP
TAB HTAB
WS WSP (SP / HTAB)
NL LF (config files are LF-terminated; parse.y's '\n')
CR, LF CR, LF
— CRLF, LWSP

In the folded design these are grammar rules like any other:

  • Where whitespace counts: a whitespace character is significant exactly where the grammar references it, and a separator everywhere else. The generator decides this when it builds the scanner, so it costs nothing at run time.
  • LF: one per line feed. Backslash-newline is a continuation and produces none. A # comment ends before the line feed, as in parse.y.
  • The daemon grammars: they use LF where parse.y has '\n', and optnl as *LF.
  • Cost: roughly one more token per line. Matched whitespace is skipped, never stored in the tree.

ws in hbnf_schema.hbnf (1*( "\n" / comment )) is not WSP: it is RFC 5234 §4's c-nl (comment / CRLF) repeated.
